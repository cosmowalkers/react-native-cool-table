# RN 0.72 / React 18 / Expo 49 升级实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 react-native-cool-table 从 RN 0.63/React16/bob0.18 时代整体升级到 RN 0.72/React 18.2/builder-bob 0.23,并把 example 升到 Expo 49,库对外 API 与业务逻辑保持不变。

**Architecture:** 换壳不重写。按"运行时→类型→测试→lint→构建→hook→bug→example"顺序推进,每阶段一个可验证 gate,失败可隔离归因。库源码只做两处 bug 修复(useTreeLazyLoad 真实回归、useFilter 防御性)和 TS5/react-jsx 现代化(清理冗余 import React)。

**Tech Stack:** React Native 0.72.17, React 18.2.0, TypeScript 5.9.3, jest 29.7.0, @testing-library/react-native 12.9.0, react-native-builder-bob 0.23.2, eslint 8.57.1, husky 8.0.3, Expo 49.0.23。

## Global Constraints

- 库对外 API 完全不变:CoolTable compound component 契约(`.Cell/.Row/.Sort/.sortStatus`)、所有 props 类型不动。
- 严格 TS:禁止 `as any`、`@ts-ignore`、`@ts-expect-error`;类型导入用 `import type`。
- react 必须精确 `18.2.0`,react-test-renderer 必须精确 `18.3.1`(与 react 一致),两者由 RN 0.72.17 peer 强约束。
- react-native 精确 `0.72.17`。
- 遵循 AGENTS.md:接口 `I` 前缀、类型别名 `T` 前缀、内部 handler `_` 前缀、render helper `render` 前缀、`memo(forwardRef(...))` 模式、单引号 2 空格 trailingComma es5。
- Conventional Commits(commitlint 强制):`feat/fix/chore/docs/refactor/test/style/perf/ci`,中文描述。
- **不自动 push,不自动做未在计划内的 commit。** 每个 Task 的 commit 步骤照做(这是计划的一部分),但推送由用户决定。
- 已知 pre-existing 测试失败:`inlineEdit` 的 `onEditCancel` 用例与实现契约矛盾,非本次回归,判定"全绿"时豁免它。

    }

        if (column) {

        }

          onFilterChangeRef.current({ filters: [], column: firstCol });
        }
      }
    }
  }, [filterStates]);
